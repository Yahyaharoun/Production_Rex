# RÈGLES FRONTEND — ERP TRANSPORT

Vous travaillez sur le frontend d’un ERP de gestion d’agence de transport de niveau production pour une véritable société de transport au Cameroun.
Ce n’est PAS un projet de démonstration.

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES GÉNÉRALES
━━━━━━━━━━━━━━━━━━━━━━━━━━

- Toujours écrire un code prêt pour la production
- Ne jamais générer de composants placeholders
- Ne jamais utiliser de fausses données/mock data sauf demande explicite
- Ne jamais générer une interface amateur
- Toujours utiliser TypeScript strictement
- Toujours utiliser des composants réutilisables
- Toujours optimiser les performances
- Toujours garder les composants modulaires et scalables
- Toujours appliquer les principes de clean architecture

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES DU STACK TECHNIQUE
━━━━━━━━━━━━━━━━━━━━━━━━━━

Le stack frontend est STRICTEMENT :

- React.js
- TypeScript
- Vite
- TailwindCSS
- Shadcn UI
- Zustand
- TanStack Query
- Axios
- React Hook Form
- Zod
- Recharts
- Framer Motion

Ne jamais utiliser :
- Redux
- Material UI
- Bootstrap
- jQuery
- CSS Modules

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES UI/UX
━━━━━━━━━━━━━━━━━━━━━━━━━━

Style de design :
- SaaS premium
- inspiré de Stripe, Linear, Notion et Uber

Thème :
- sombre professionnel
- espacement élégant
- animations fluides

Couleurs :
- arrière-plan #0f0f0f
- panneaux #1a1a2e
- accent #f59e0b

Exigences UI :
- responsive mobile-first
- navigation latérale (sidebar)
- skeleton loaders
- états vides
- error boundaries
- boîtes de dialogue de confirmation
- notifications toast
- badges de statut
- cartes réutilisables
- tableaux réutilisables

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES D’ORGANISATION DU CODE
━━━━━━━━━━━━━━━━━━━━━━━━━━

Utiliser cette structure :

src/
 ├── app/
 ├── routes/
 ├── pages/
 ├── modules/
 ├── components/
 ├── layouts/
 ├── services/
 ├── store/
 ├── hooks/
 ├── utils/
 ├── types/
 ├── providers/

Règles :
- chaque fonctionnalité doit être modulaire
- éviter la duplication de logique
- séparer la logique métier de l’interface utilisateur
- composants de formulaires réutilisables
- composants de tableaux réutilisables
- système de modales réutilisable

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES API
━━━━━━━━━━━━━━━━━━━━━━━━━━

- Utiliser une instance Axios centralisée
- Utiliser des intercepteurs
- Gérer automatiquement les JWT
- Gérer automatiquement les refresh tokens
- Centraliser les erreurs API
- Utiliser TanStack Query partout

Ne jamais effectuer des fetchs directement dans les composants.

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES DES FORMULAIRES
━━━━━━━━━━━━━━━━━━━━━━━━━━

Tous les formulaires doivent :
- utiliser React Hook Form
- utiliser la validation Zod
- afficher les erreurs de validation inline
- supporter les états de chargement
- supporter les états désactivés
- supporter les mises à jour optimistes lorsque pertinent

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES DE PERFORMANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━

Toujours :
- lazy loader les pages
- utiliser le code splitting
- optimiser la taille du bundle
- mémoriser les composants coûteux
- paginer les tableaux
- virtualiser les grandes listes lorsque nécessaire

Optimiser pour :
- faible bande passante
- anciens ordinateurs
- connexion internet instable

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES OFFLINE
━━━━━━━━━━━━━━━━━━━━━━━━━━

Implémenter :
- cache local IndexedDB
- file d’attente hors ligne
- synchronisation automatique
- mécanisme de retry

━━━━━━━━━━━━━━━━━━━━━━━━━━
RÈGLES DE SÉCURITÉ
━━━━━━━━━━━━━━━━━━━━━━━━━━

Ne jamais :
- stocker les tokens de manière non sécurisée
- exposer des données sensibles
- faire confiance uniquement à la validation frontend

Toujours :
- protéger les routes
- gérer les états non autorisés
- déconnecter automatiquement les sessions expirées
